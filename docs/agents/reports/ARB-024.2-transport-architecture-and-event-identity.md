# ARB-024.2 — Transport Architecture & Event Identity: Implementation Report

## Context

ARB-024.1 established the publication boundary: application services write to the Outbox exclusively; the relay owns the transport layer. ARB-024.2 establishes the transport package structure, introduces stable logical event identity via `EventDescriptor`, and prepares the inputs for future Schema Registry subject naming — without implementing Kafka publishing, relay polling, or Schema Registry integration.

## Event Identity Design

### Choice: Approach A — `DomainEvent.descriptor()`

Three approaches were evaluated:

| Approach | Description | Verdict |
|---|---|---|
| **A — interface method** | `DomainEvent.descriptor()` | **Chosen** |
| B — annotation | `@EventDescriptor(type=...)` | Rejected — requires reflection at transport time |
| C — external registry | Map class → descriptor externally | Rejected — adds indirection, hides intent |

**Approach A** is simplest: the domain event explicitly declares its identity without transport coupling. The descriptor contains only `type` (String) and `version` (int) — no Kafka, no Avro, no Spring.

### `EventDescriptor`

```java
// platform.messaging.event
public record EventDescriptor(String type, int version) {
    // type: blank rejected; version: must be >= 1
}
```

`type` is a dot-separated logical name stable across Java refactors. `version` is an integer (1, 2, …); transport adapters encode it as `"v1"`, `"v2"`, etc.

### `DomainEvent` interface

```java
// platform.messaging.event
public interface DomainEvent {
    EventDescriptor descriptor();
}
```

No Spring, no Kafka, no persistence dependencies. Lives in `platform.messaging.event` so `DomainEventToOutboxMapper` can read it without the order-service domain depending on the transport layer.

### `OrderCreatedDomainEvent`

```java
public record OrderCreatedDomainEvent(...) implements DomainEvent {
    @Override
    public EventDescriptor descriptor() {
        return new EventDescriptor("order.created", 1);
    }
}
```

The outbox `eventType` column now stores `"order.created"` instead of `"OrderCreatedDomainEvent"`. This value is stable under Java refactoring.

## `DomainEventToOutboxMapper` Update

```java
// Before:
message.getClass().getSimpleName()

// After:
(message instanceof DomainEvent de) ? de.descriptor().type() : message.getClass().getSimpleName()
```

The fallback to `getSimpleName()` preserves backward compatibility for any outbound messages (commands, legacy events) that do not implement `DomainEvent`. The existing test `falls_back_to_class_simple_name_when_domain_event_not_implemented` covers this path.

## `TransportEventMetadata`

```java
// adapter/outbound/transport/model
public record TransportEventMetadata(String eventType, String eventVersion) {
    public static TransportEventMetadata from(EventDescriptor descriptor) {
        return new TransportEventMetadata(descriptor.type(), "v" + descriptor.version());
    }
}
```

Bridges domain identity (int version) to transport string encoding (`"v1"`). Used by Avro and JSON adapters to populate Kafka headers, Avro schema version fields, and (future) Schema Registry subject naming.

## Architecture Enforcement Update

`ArchitectureTest` rule renamed and updated:

```java
@Test
void application_must_not_depend_on_transport_adapters() {
    ArchRuleDefinition.noClasses().that().resideInAPackage("..application..")
            .should().dependOnClassesThat().resideInAPackage("..adapter.outbound.transport..")
            .because("application services publish through OutboxRepository; " +
                     "transport publication adapters belong in the adapter/outbound/transport layer")
            .allowEmptyShould(true)
            .check(classes);
}
```

Previously checked `..adapter.outbound.kafka..`. Now checks the full transport hierarchy.

## Subject Strategy Preparation (ARB-024.x input)

The transport layer can now derive Schema Registry subject names without depending on Java class names:

```
OrderCreatedDomainEvent.descriptor()
  → EventDescriptor("order.created", 1)
  → TransportEventMetadata.from(descriptor)
  → TransportEventMetadata(eventType="order.created", eventVersion="v1")
  → future SubjectNameStrategy.toSubject(meta)
  → "order.created-v1" or "arbitrier.order.OrderCreated-value" (to be decided in ARB-024.x)
```

The subject naming strategy is deliberately **not** implemented here — the inputs are established. The relay owns the `eventType` → subject resolution.
