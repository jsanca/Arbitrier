## Summary

Eliminated the duplicated retry orchestration in `DispatchOutboxMessageService` by extracting a single `handleRetryOrStop` method that owns `RetryPolicy` evaluation, `BackoffStrategy` + `RetryScheduler` invocation, `markFailed`, `DeadMessageHandler` delegation, and final failure propagation. Both the synchronous-throw path and the async-failure path now delegate to this one method. As a consequence, the synchronous path no longer throws directly — it returns a failed `CompletionStage` — making the dispatcher's observable failure contract consistent across both paths.

## Architectural Decisions

### 1. Extracted `handleRetryOrStop` owns the full failure pipeline

```java
private CompletionStage<Void> handleRetryOrStop(final OutboxEvent message,
                                                 final int attempt,
                                                 final Throwable failure) {
    final RetryDecision decision = retryPolicy.evaluate(attempt, failure);
    if (decision.shouldRetry()) {
        final int next = attempt + 1;
        final BackoffDelay delay = backoffStrategy.nextDelay(next);
        return retryScheduler.schedule(() -> attemptDispatch(message, next), delay);
    }
    callMarkFailed(message, failure);
    return deadMessageHandler.handle(deadContext(message, attempt, failure))
            .handle((ignored, handlerEx) -> (Void) null)
            .thenCompose(ignored -> CompletableFuture.failedFuture(failure));
}
```

`RetryPolicy`, `BackoffStrategy`, `RetryScheduler`, `markFailed`, and `DeadMessageHandler` are all invoked in exactly one place. Adding or changing behavior in any of these collaborators now requires changing one method, not two.

### 2. `attemptDispatch` is now a thin dispatcher

```java
private CompletionStage<Void> attemptDispatch(final OutboxEvent message, final int attempt) {
    final CompletionStage<Void> published;
    try {
        published = publisher.publish(message);
    } catch (final RuntimeException immediate) {
        return handleRetryOrStop(message, attempt, immediate);
    }
    return published.exceptionallyCompose(pubEx -> handleRetryOrStop(message, attempt, pubEx));
}
```

`attemptDispatch` handles only the try/catch boundary. Failure semantics belong entirely in `handleRetryOrStop`.

### 3. Synchronous throw → failed `CompletionStage`

The previous sync path threw `immediate` directly after fire-and-forgetting the `DeadMessageHandler`. The unified path returns a failed `CompletionStage` carrying the original cause. This is a behavioral alignment, not a behavioral change from the caller's perspective: `dispatch()` still fails with the original cause; the difference is whether that failure is a synchronous throw or a `CompletionStage` completed exceptionally.

The test `immediate_publication_failure_calls_markFailed` was updated from `assertThatThrownBy` to `assertThat(result.isCompletedExceptionally()).isTrue()` to match the unified contract. No other tests required changes.

### 4. `DeadMessageHandler` is now always sequenced — never fire-and-forget

The old sync STOP path fired the handler as a side-effect and discarded its `CompletionStage`. The unified path always sequences `markFailed → handle → failedFuture`. This is strictly better: handler completions are now ordered, and any async handler (future DLQ writer) will be awaited before the dispatch stage completes exceptionally.

## Implementation Notes

## Tradeoffs

- Callers that previously relied on `dispatch()` throwing synchronously for a sync publisher failure must now observe the failure via `CompletionStage`. No external callers in this codebase do this — all callers chain on the returned stage — so this is a safe change. The test was the only consumer of the synchronous-throw behavior, and it has been updated.
- The unified path always awaits the `DeadMessageHandler` result (via `.handle().thenCompose()`), which is stricter than the old fire-and-forget. This only matters for handlers that do non-trivial async work; `LoggingDeadMessageHandler` is synchronous, so the behavior in all current tests is unchanged.
