## Summary

Introduced three types in `platform.messaging.retry` — `RetryPolicy`, `RetryDecision`, and `SimpleRetryPolicy` — that encapsulate retry decisions independently from the dispatcher implementation. `DispatchOutboxMessageService` now depends on `RetryPolicy` and implements a synchronous retry loop using the policy, with no delay in this slice. A 2-argument convenience constructor defaults to `SimpleRetryPolicy(1)` (try once, no retry) so that existing tests and callers compile and behave identically.

## Architectural Decisions

### 1. `RetryDecision` is a record, not a sealed interface

`RetryDecision(boolean shouldRetry, int attempt, int maxAttempts)` is a plain record with static factory methods `retry(attempt, maxAttempts)` and `stop(attempt, maxAttempts)`. A sealed interface hierarchy (`Retry`, `Stop`) was considered but rejected: the three fields carry all the context needed; pattern matching on the sealed type would add syntax with no behavioural gain in this slice.

### 2. `attempt` is 1-indexed

`evaluate(int attempt, Throwable failure)` receives the 1-indexed number of the attempt that just failed. `SimpleRetryPolicy(maxAttempts=1)` therefore evaluates `attempt=1` → STOP, matching the original single-attempt behaviour exactly. This preserves existing test contracts without modification.

### 3. 2-argument convenience constructor on `DispatchOutboxMessageService`

The existing 2-argument constructor is kept as a convenience that delegates to the 3-argument form with `new SimpleRetryPolicy(1)`. All eight existing unit tests pass without modification. New callers that need retries must supply an explicit `RetryPolicy`.

### 4. Retry loop is recursive `CompletionStage` composition — no blocking

Retries are chained as recursive `CompletionStage` calls inside `attemptDispatch`. No `get()` or `join()` is called; the virtual-thread executor handles the chain. Delay and backoff are deferred to ARB-022.6.2; the loop is currently immediate.

### 5. `markFailed` is called only on final failure

Unlike the original code (which called `markFailed` on every failure), the refactored dispatcher calls `markFailed` only when the policy returns STOP. This is correct: transient failures consumed by a retry must not mark the message permanently failed.

## Implementation Notes

`DispatchOutboxMessageService` was split into a public `dispatch()` entry point and a private recursive `attemptDispatch(message, attempt)`. The `thenRun(markPublished)` is chained outside the retry loop so it is called exactly once after all attempts succeed.

`SimpleRetryPolicy` is declared `final` — it is a leaf implementation and CGLIB proxying is not needed for a concrete strategy class.

## Tradeoffs

- The synchronous retry loop (no delay) is intentional for this slice. Immediate retries on a transient Kafka failure are unlikely to succeed, but delay is out of scope here and will be addressed in ARB-022.6.2. In the current single-attempt default configuration (`SimpleRetryPolicy(1)`) no retries occur at all, so this has no observable production impact.
- `RetryDecision` could omit `maxAttempts` and let callers infer it from `SimpleRetryPolicy.maxAttempts()`. Carrying `maxAttempts` in the decision makes each `RetryDecision` self-describing for logging and future backoff calculation without a back-reference to the policy.
