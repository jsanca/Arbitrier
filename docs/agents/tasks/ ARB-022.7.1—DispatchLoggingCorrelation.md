Objective

Introduce structured runtime logging for the messaging dispatcher so every dispatch operation can be traced through a consistent set of log events.

This task focuses exclusively on logging and correlation.

No metrics or Micrometer integration are introduced.

## Context

The retry pipeline is now complete.

Operators should be able to understand dispatcher activity using logs alone.

This slice establishes the logging vocabulary that later metrics and tracing will complement.

## Scope
In Scope

Add structured log events for:

dispatch started
dispatch succeeded
retry scheduled
retry exhausted
dead message delegated

Each log should include, where available:

eventId
aggregateId
aggregateType
eventType
attempt number
retry decision
delay
correlationId (if present)

Use the project's structured logging conventions.

Avoid duplicated log messages.

## Correlation

Reuse the existing messaging context.

Do not introduce new correlation mechanisms.

If a correlation identifier already exists on the event, include it consistently in every dispatch log.

## Out of Scope

Do not introduce:

Micrometer
Prometheus
OpenTelemetry
tracing spans
timing metrics
counters
gauges

Logging only.

## Acceptance Criteria
Dispatch lifecycle is fully observable through logs.
Retry attempts produce meaningful log entries.
Dead-message delegation is logged once.
Correlation identifiers flow consistently.
Existing behavior unchanged.
Existing tests pass.

Structured logging improvements
