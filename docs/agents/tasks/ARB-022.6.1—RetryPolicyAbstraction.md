### Objective
    
Introduce a transport-agnostic retry policy abstraction that encapsulates retry decisions independently from the event dispatcher implementation.

The dispatcher must no longer contain retry-specific logic or constants.

### Context

ConcurrentEventDispatcher is responsible for asynchronous event publication.

Upcoming work will introduce:

- Exponential backoff
- Scheduled retries
- Dead message handling

Before implementing those capabilities, retry decisions must be extracted behind a dedicated policy abstraction.

This task only introduces the abstraction and a simple default implementation.

### Scope
In Scope

Implement:

platform
└── messaging
└── retry
├── RetryPolicy
├── RetryDecision
└── SimpleRetryPolicy

The policy must expose retry decisions without performing scheduling.

Example API (exact naming may vary):

public interface RetryPolicy {

    RetryDecision evaluate(
        int attempt,
        Throwable failure
    );

}

RetryDecision should represent:

- retry or stop
- current attempt
- maximum attempts

No delay calculation yet.

Provide a default implementation supporting:

configurable maximum attempts
retry until maximum attempts reached
### Out of Scope

Do not implement:

exponential backoff
delays
scheduler
ScheduledExecutorService
dead message handling
Kafka-specific behavior
persistence
metrics additions
